# Does the Code Graph Find the Bug? The harness's graph tools vs plain keyword search for issue localisation

The `swegemma` harness gives your agent three code-graph tools: `search_similar_code`, `get_code_neighbors`
and `get_code_subgraph`. Each call costs one of a small tool budget (10 in the sample submission). This notebook
treats them as a **retrieval benchmark**. For every task, the `problem_statement` is the query, and the files
and symbols the reference `patch` touches are the gold answers. Do the tools surface them, and at what k?

##### [markdown 4]
## 1. Framing and questions

An agent that is handed an issue wants to land in the right file within the first couple of tool calls. So the
metric is **file recall@k**: the share of the patch's gold files that contain at least one of the top-k returned
graph nodes. **Symbol recall@k** (the share of gold functions or classes returned) is the stricter companion.

Questions:
1. How far does a query-free baseline get (random nodes, most-connected nodes)?
2. How far does plain lexical retrieval over node text get (BM25, TF-IDF)?
3. How do the three graph tools compare when queried as the harness allows?
4. Does the answer hold across repos, or is it a FastAPI artefact?
5. Which tool, and which k, should a system prompt push?

**How the tools are reimplemented** (HARNESS_README §6.3), with each approximation stated:
- `search_similar_code(query, k)`: there is no query encoder offline. A single-token query resolves to a node
  through `resolve_node_name`. A multi-word query uses the lexical token-overlap fallback to pick an anchor node.
  Results are the k nodes most cosine-similar to the anchor, excluding the anchor itself.
  *Assumptions (not specified in the README):* the anchor is the node whose key tokens overlap the query most
  (ties go to the shortest key), and ties within a resolution tier also go to the shortest name.
- `get_code_neighbors(node)`: out-neighbours, then in-neighbours, capped at 50 names and 5,000 characters.
  *Assumption:* this order (out before in, in edge-list order) is not specified in the README. The seeds
  themselves are **not** scored, so the tool only gets credit for nodes it actually adds. §6.3 documents no
  lexical fallback for this tool, so the raw issue text has to resolve through the 4 name tiers (it almost never does).
- `get_code_subgraph(nodes)`: the induced subgraph returns **only the nodes you pass in**, so it cannot discover
  anything. Its "recall" is simply what you get by looking up the names the issue mentions. It is therefore
  reported as a reference line, **Direct lookup of issue identifiers**, and never competes as a graph tool.

The "best graph tool" is picked only among the four **discovery** variants that can return nodes they were not
given: `search_similar_code` and `get_code_neighbors`, each queried with the raw statement or with identifiers.

The identifier-seeded variants mimic what the sample system prompt asks an agent to do: pull up to 5 code-like
identifiers out of the issue (backticked spans, `snake_case`, `CamelCase`, dotted paths, `.py` paths) and spend one
call on each.

## 2. Data and gold labels

The gold labels come from the `patch` only (never `test_patch`). Each changed file maps to a graph module by
matching the longest dotted suffix of its path against the graph's module names. For example, `docs_src/` is
stripped in the FastAPI graphs. Each node's module is its longest dotted prefix that is not itself a node.
Gold symbols are the nodes in a gold module whose text contains a removed line. For pure insertions, the
surrounding context lines stand in. A line that appears in more than 3 nodes counts as generic and is ignored.
New files (`--- /dev/null`) cannot be retrieved from the pre-fix graph, so they are excluded from the denominators
and counted separately.

##### [code 6]
FILE_RE = re.compile(r"^--- (a/(\S+)|/dev/null)\n\+\+\+ (b/(\S+)|/dev/null)\n", re.M)
FUNC_RE = re.compile(r"(?:def|class)\s+(\w+)")


def changed_blocks(body: list[str]) -> list[str]:
    """Old-side anchor lines: removed lines, or the context around a pure insertion."""
    anchors, i = [], 0
    is_change = lambda s: bool(s) and s[0] in "+-"
    while i < len(body):
        if not is_change(body[i]) or body[i].startswith("@@"):
            i += 1
            continue
        j = i
        while j < len(body) and is_change(body[j]):
            j += 1
        minus = [b[1:] for b in body[i:j] if b.startswith("-")]
        ctx = [body[k][1:] for k in [*range(i - 2, i), *range(j, j + 2)] if 0 <= k < len(body) and body[k][:1] == " "]
        anchors += minus or ctx
        i = j
    return [a.strip() for a in anchors if len(a.strip()) >= 8]

##### [code 7]
def parse_patch(patch: str) -> dict:
    """{path: (anchor_lines, hunk_funcs)}; new files map to None."""
    out, ms = {}, list(FILE_RE.finditer(patch))
    for m, nxt in zip(ms, ms[1:] + [None]):
        body = patch[m.end(): nxt.start() if nxt else len(patch)].split("\n")
        if m.group(2) is None:
            out[m.group(4)] = None
            continue
        funcs = [f for ln in body if ln.startswith("@@") for f in FUNC_RE.findall(ln.split("@@")[-1])]
        out[m.group(2)] = (changed_blocks(body), funcs)
    return out

##### [code 8]
def toks(s: str) -> list[str]:
    s = re.sub(r"([a-z0-9])([A-Z])", r"\1 \2", s)
    return [t for t in re.findall(r"[a-z0-9]+", s.lower()) if len(t) > 2]


def module_of(name: str, nodeset: set) -> str:
    parts = name.split(".")
    for j in range(len(parts) - 1, 0, -1):
        if ".".join(parts[:j]) not in nodeset:
            return ".".join(parts[:j])
    return parts[0]


def file_module(path: str, modules: set) -> str | None:
    if not path.endswith(".py"):
        return None
    parts = path[:-3].split("/")
    parts = parts[:-1] if parts[-1] == "__init__" else parts
    return next((".".join(parts[i:]) for i in range(len(parts)) if ".".join(parts[i:]) in modules), None)

##### [code 9]
def load_snapshot(snap: str) -> dict:
    g = json.loads((DATA / "graphs" / f"{snap}.json").read_text(encoding="utf-8"))
    names = [n["name"] for n in g["nodes"]]
    texts = [n.get("text") or "" for n in g["nodes"]]
    idx = {n: i for i, n in enumerate(names)}
    out_adj, in_adj = defaultdict(list), defaultdict(list)
    for e in g["edges"]:
        s, t = idx.get(e["source"]), idx.get(e["target"])
        if s is not None and t is not None:
            out_adj[s].append(t)
            in_adj[t].append(s)
    z = np.load(DATA / "embeddings" / f"{snap}.npz")
    keys = set(z.files)
    E = np.stack([z[n] if n in keys else np.zeros(256, np.float32) for n in names]).astype(np.float32)
    E /= np.linalg.norm(E, axis=1, keepdims=True).clip(1e-9)
    nodeset = set(names)
    module = [module_of(n, nodeset) for n in names]
    return dict(names=names, texts=texts, idx=idx, out=out_adj, inn=in_adj, E=E, module=module,
                modules=set(module), lines=[{ln.strip() for ln in t.split("\n")} for t in texts])

##### [code 10]
def gold_for(patch: str, S: dict) -> dict:
    parsed = parse_patch(patch)
    new = sum(v is None for v in parsed.values())
    mods, syms, unmapped, mapped = set(), set(), 0, 0
    for path, v in parsed.items():
        mod = file_module(path, S["modules"]) if v is not None else None
        if v is None:
            continue
        if mod is None:
            unmapped += path.endswith(".py")
            continue
        mods.add(mod)
        mapped += 1
        cand = [i for i, m in enumerate(S["module"]) if m == mod]
        found = set()
        for a in v[0]:
            hits = [i for i in cand if a in S["lines"][i]]
            if 1 <= len(hits) <= 3:
                found.add(min(hits, key=lambda i: len(S["texts"][i])))
        if not found:  # fall back on git's hunk-header function names
            found = {i for i in cand if S["names"][i].rsplit(".", 1)[-1] in v[1]}
        syms |= found
    return dict(gold_mods=mods, gold_syms=syms, n_new=new, n_unmapped=unmapped, n_mapped=mapped, n_files=len(parsed))

##### [markdown 11]
## 3. Validation and leakage

Nothing is trained on the gold labels except the BM25 hyper-parameters (k1, b). These are tuned with
**leave-one-repo-out** CV. Grouping by repo, not by task, matters for three reasons:
- Two pairs of tasks share a `base_commit` (`rich_3882`/`rich_3894`, `requests_6629`/`requests_6589`), so they
  share one graph.
- Snapshots of the same repo at nearby commits are near-identical graphs, so a task-level split would let the
  tuner see the test repo.
- `encode/httpx` has a single task, so it is folded into the `psf/requests` group (both HTTP clients). This is
  conservative: it merges groups and never splits one.

Every result is reported as the **mean ± std across repo groups**, not across tasks, so FastAPI's 67 tasks cannot
dominate. With only 3 groups, the std is descriptive (how much repos disagree), not a confidence interval. The gold labels never feed the queries. The graph is the pre-fix snapshot, so it contains no future code.
The remaining leak is in the issue text itself: some PR descriptions name the very function they change. Section 9
splits the results on exactly that.

##### [code 12]
URL_RE = re.compile(r"https?://\S+|<!--.*?-->", re.S)
IDENT_RE = re.compile(r"[A-Za-z_][\w./]*\w")
NOT_CODE = {"GitHub", "JavaScript", "TypeScript", "YouTube", "macOS", "PyPI", "PyCharm", "VSCode"}


def identifiers(text: str) -> list[str]:
    text = URL_RE.sub(" ", text)
    ticked = {t for span in re.findall(r"`([^`\n]{3,120})`", text) for t in IDENT_RE.findall(span)}
    keep = []
    for c in sorted(IDENT_RE.findall(text), key=lambda c: c not in ticked):  # backticked first, stable order
        c = c.strip("./")
        c = c[:-3].replace("/", ".") if c.endswith(".py") else c
        code_like = "_" in c or "." in c or re.search(r"[a-z][A-Z]|[A-Z]{2,}[a-z]", c)
        if "/" in c or len(c) < 4 or c in keep or c in NOT_CODE or re.fullmatch(r"v?\d[\w.]*|e\.g|i\.e|_+[a-z]+_+", c):
            continue
        if code_like or c in ticked:
            keep.append(c)
    return keep


def resolve(q: str, S: dict) -> int | None:
    """resolve_node_name: exact -> ./;// suffix -> case-insensitive -> substring (ties: shortest name)."""
    if q in S["idx"]:
        return S["idx"][q]
    ql = q.lower()
    for test in (lambda n: n.endswith(("." + q, ";" + q, "/" + q)), lambda n: n.lower() == ql, lambda n: q in n):
        hits = [i for i, n in enumerate(S["names"]) if test(n)]
        if hits:
            return min(hits, key=lambda i: len(S["names"][i]))
    return None

##### [code 13]
def seeds_for(statement: str, S: dict) -> list[int]:
    seeds = []
    for c in identifiers(statement):
        i = resolve(c, S)
        if i is not None and i not in seeds:
            seeds.append(i)
        if len(seeds) == MAX_SEEDS:
            break
    return seeds


def round_robin(lists: list[list[int]], head: list[int] = (), cap: int = max(KS)) -> list[int]:
    out = list(dict.fromkeys(head))
    for row in zip(*[lst + [None] * (cap - len(lst)) for lst in lists] or [[]]):
        out += [i for i in row if i is not None and i not in out]
    return out[:cap]

##### [code 14]
def cosine_top(i: int, S: dict, k: int = max(KS)) -> list[int]:
    sims = S["E"] @ S["E"][i]
    sims[i] = -np.inf
    return list(np.argsort(-sims)[:k])


def neighbors(i: int, S: dict) -> list[int]:
    nb, chars = [], 0
    for j in dict.fromkeys(S["out"][i] + S["inn"][i]):
        chars += len(S["names"][j]) + 4
        if len(nb) == MAX_NEIGHBORS or chars > MAX_CHARS:
            break
        nb.append(j)
    return nb

##### [markdown 15]
## 4. No-retrieval baselines

Two query-free baselines come first. **Random k** is the *analytic* expected recall of k nodes drawn uniformly
without replacement: a gold module with n of N nodes is hit with probability 1 − C(N−n, k)/C(N, k), and a gold
symbol with probability k/N. **Degree prior** returns the most-connected nodes in the call graph, the same list for
every task. Any tool that cannot beat these is not reading the issue.

##### [code 16]
def p_miss(N: int, n: int, k: int) -> float:
    """P(k draws without replacement from N miss all n targets) = C(N-n, k) / C(N, k)."""
    if n == 0:
        return 1.0
    if N - n < k:
        return 0.0
    return exp(lgamma(N - n + 1) - lgamma(N - n - k + 1) - lgamma(N + 1) + lgamma(N - k + 1))


def random_expected(g: dict, S: dict, k: int) -> dict:
    N, size = len(S["names"]), Counter(S["module"])
    return {"file_recall": float(np.mean([1 - p_miss(N, size[m], k) for m in g["gold_mods"]])),
            "sym_recall": min(k, N) / N if g["gold_syms"] else np.nan,
            "hit": 1 - p_miss(N, sum(size[m] for m in g["gold_mods"]), k)}


def degree_rank(S: dict) -> list[int]:
    deg = np.array([len(S["out"][i]) + len(S["inn"][i]) for i in range(len(S["names"]))])
    return list(np.argsort(-deg, kind="stable")[: max(KS)])

##### [markdown 17]
## 5. Lexical baselines (BM25, TF-IDF)

Both baselines index every node as `name + text`, using the same camelCase- and snake_case-splitting tokenizer,
and query with the raw `problem_statement`. This is roughly what a strong `grep`-style search over the graph would
give an agent. The BM25 grid (k1 × b) and the field ablation (name only, text only, both) are kept for sections 7 and 8.

##### [code 18]
BM25_GRID = [(k1, b) for k1 in (0.6, 1.2, 2.0) for b in (0.25, 0.5, 0.75, 1.0)]
FIELDS = {"name": lambda S: [" ".join(n.split(".")) for n in S["names"]], "text": lambda S: S["texts"],
          "both": lambda S: [n.replace(".", " ") + " " + t for n, t in zip(S["names"], S["texts"])]}


def bm25_index(docs: list[str]) -> dict:
    cv = CountVectorizer(tokenizer=toks, lowercase=False, token_pattern=None)
    X = cv.fit_transform(docs).tocsc().astype(np.float32)
    df = np.diff(X.indptr)
    idf = np.log(1 + (X.shape[0] - df + 0.5) / (df + 0.5))
    return dict(cv=cv, X=X, idf=idf, dl=np.asarray(X.sum(1)).ravel())


def bm25_rank(ix: dict, query: str, k1: float = 1.2, b: float = 0.75) -> list[int]:
    cols = np.unique(ix["cv"].transform([query]).indices)
    if len(cols) == 0:
        return []
    tf = ix["X"][:, cols].toarray()
    norm = k1 * (1 - b + b * ix["dl"] / max(ix["dl"].mean(), 1e-9))
    scores = (tf * (k1 + 1) / (tf + norm[:, None])) @ ix["idf"][cols]
    return list(np.argsort(-scores, kind="stable")[: max(KS)])


def tfidf_rank(S: dict, query: str) -> list[int]:
    tv = TfidfVectorizer(tokenizer=toks, lowercase=False, token_pattern=None, sublinear_tf=True)
    X = tv.fit_transform(FIELDS["both"](S))
    scores = (X @ tv.transform([query]).T).toarray().ravel()
    return list(np.argsort(-scores, kind="stable")[: max(KS)])

## 6. The three graph tools

Each method below returns a ranked list of up to 50 node indices per task. Identifier seeds are shared across the
three identifier-based variants, so the comparison is apples to apples: same seeds, same number of calls.

##### [code 20]
def search_statement(S: dict, query: str, name_ix: dict) -> list[int]:
    """search_similar_code(problem_statement): lexical fallback picks an anchor, then cosine top-k."""
    q = np.zeros(name_ix["X"].shape[1], np.float32)
    q[np.unique(name_ix["cv"].transform([query]).indices)] = 1
    overlap = (name_ix["X"] > 0).astype(np.float32) @ q
    if overlap.max() <= 0:
        return []
    anchor = int(np.argmax(overlap - 1e-3 * name_ix["dl"]))  # most overlap, shortest key on ties
    return cosine_top(anchor, S)


def neighbors_statement(S: dict, statement: str) -> list[int]:
    """get_code_neighbors(problem_statement): no lexical fallback in §6.3, so only the 4 name tiers can resolve it."""
    i = resolve(statement.strip(), S)
    return [] if i is None else neighbors(i, S)


def methods_for(S: dict, statement: str, ixs: dict) -> tuple[dict, list[int]]:
    seeds = seeds_for(statement, S)
    return {
        "Degree prior (no query)": degree_rank(S),
        "BM25 · statement": bm25_rank(ixs["both"], statement),
        "TF-IDF · statement": tfidf_rank(S, statement),
        "search_similar_code · statement": search_statement(S, statement, ixs["name"]),
        "search_similar_code · identifiers": round_robin([cosine_top(s, S) for s in seeds]),
        "get_code_neighbors · statement": neighbors_statement(S, statement),
        "get_code_neighbors · identifiers": round_robin([[j for j in neighbors(s, S) if j not in seeds] for s in seeds]),
        LOOKUP: list(seeds),
    }, seeds

##### [code 21]
def score(rank: list[int], g: dict, S: dict, k: int) -> dict:
    top = rank[:k]
    got_mods = {S["module"][i] for i in top}
    fr = len(got_mods & g["gold_mods"]) / len(g["gold_mods"])
    sr = len(set(top) & g["gold_syms"]) / len(g["gold_syms"]) if g["gold_syms"] else np.nan
    return {"file_recall": fr, "sym_recall": sr, "hit": float(fr > 0)}


def names_gold(statement: str, g: dict, S: dict) -> bool:
    shorts = {S["names"][i].rsplit(".", 1)[-1] for i in g["gold_syms"]}  # symbol names only, not module names
    shorts = {s for s in shorts if len(s) >= 4 and not s.startswith("__")}
    return any(re.search(rf"\b{re.escape(s)}\b", statement) for s in shorts)

### Results table (mean ± std across repo groups)

The BM25 row tuned with leave-one-repo-out CV is added here. For each held-out repo group, (k1, b) is chosen
to maximise file recall@10 on the other groups, then scored on the held-out one.

##### [code 30]
def loro_bm25(grid: pd.DataFrame) -> pd.DataFrame:
    groups, out = grid.group.unique(), []
    for held in groups:
        train = grid[(grid.group != held) & (grid.k == K_MAIN)]
        if train.empty:  # a single group cannot be cross-validated; fall back to the default (1.2, 0.75)
            k1, b = 1.2, 0.75
        else:
            k1, b = train.groupby(["k1", "b"]).file_recall.mean().idxmax()
        test = grid[(grid.group == held) & (grid.k1 == k1) & (grid.b == b)]
        out.append(test.assign(method=f"BM25 · tuned LORO", chosen=f"k1={k1}, b={b}"))
    return pd.concat(out)

##### [markdown 32]
### Selection effect: is the "best tool" pick honest?

`best_tool` and its k are picked on the same tasks they are reported on, so its in-sample number is optimistic.
The check below re-picks the tool with leave-one-repo-out: choose on two groups, score on the third.

##### [code 33]
def loro_tool(res: pd.DataFrame) -> pd.DataFrame:
    at, out = res[(res.k == K_MAIN) & res.method.isin(TOOLS)], []
    for held in at.group.unique():
        tr = at[at.group != held]
        pick = (tr if not tr.empty else at).groupby("method").file_recall.mean().idxmax()
        out.append({"held_out": held, "picked": pick, "honest": not tr.empty,
                    "file_recall": at[(at.group == held) & (at.method == pick)].file_recall.mean()})
    return pd.DataFrame(out)

**Next steps**
- **A real query encoder.** If the harness ever exposes one, re-run `search_similar_code · statement` with the issue
  embedded directly. The lexical-anchor fallback is an assumption about undocumented behaviour.
- **Hybrid prompt policy.** Seed with issue identifiers, and when none resolve, take the top BM25 node as the seed for
  `get_code_neighbors`, and test whether that lifts the "issue names no code" segment in §9.
- **Line-level gold.** Map hunks to node line spans once the snapshots are extracted, instead of text matching.
  This would tighten symbol recall for module-level edits.
- **End-to-end check.** Does higher file recall@k predict resolved tasks in the harness? That would take agent runs,
  not this offline benchmark.
