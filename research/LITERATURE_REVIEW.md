### I.2 What the leaderboard and the forum tell us (as of 2026-10-16)

1. **The top is undifferentiated.** #1–2 at 0.24 (14/58), 25 teams tied at 0.22, 22 at 0.20. A user ranked 12th says none of the top submissions got there through fine-tuning; another analysed the score distribution and finds it consistent with pure binomial noise around two low means. The same package resubmitted scored 0.17/0.15/0.13/0.15 [FORUM 748051]. **Nobody has cracked anything yet.** A method with a *true* private-set rate of ~0.30 wins outright.

2. **Local CV on the public repos anti-correlates with the LB.** Reported pairs: CV 0.18/0.19/0.23/0.24 → LB 0.05/0.06/0.12/0.10; CV 0.21/0.24/0.32/0.29 → LB 0.10/0.08/0.03/0.05 [FORUM 744319]. Two independent teams measure a local→hidden transfer ratio of 1/3.5 to 1/5 (25/70 → 7/58; 34.5% → 6.9%). Causes: the 31B has almost certainly memorised fastapi/rich/requests/httpx (its no-retrieval localisation score on them is 0.357); the public set is 52% fastapi; private repos are different (host: synchronous Python, ≤1.8% async functions, none of the training repos appear in test); and runtime failures that never show up locally.

3. **The public grader is broken for most fastapi tasks.** Only 43/129 gold patches pass in the stock public harness (fastapi 1/67, rich 39/48, requests 3/13, httpx 0/1) because `typing_inspection` is missing from `/wheels` and bundled release wheels shadow `/workspace`. The host confirms the **hidden test set validates at 100% with gold patches** and is being fixed for training. A community-rebuilt grader gets 119/129 sound; 4 tasks pass with an empty patch (rich_3468 genuinely; 3 requests tasks only because of wheel shadowing) [FORUM 747248].

4. **Thinking is non-negotiable: ON vs OFF = 48–51 vs 23 resolved of 129** on the 31B (thought summaries off: 35) [FORUM 746250]. Temperature 0.4–1.0 ties; top-p 0.95; a 4,096 thinking budget is the sweet spot; 6,144 does not help. `include_thoughts: false` in the YAML *disables* thinking rather than hiding it.

5. **Time is the binding constraint, not tool calls.** Kaggle 4×L4 calibration for the 31B: 1,110 tok/s aggregate, 8.7 s per model call with thinking, ~900 s per million tokens; a successful trajectory is 40–50 LLM+tool calls and 300–350k tokens. **Operational cap: 5.5 min/task** (120 × 5.5 = 11 h + 1 h setup) [FORUM 746250/747857]. At a 6-min local cap the 31B drops to 28.7%; at 15 min it peaks at 41.9%. The 12B decodes ~1.9× faster (67 vs 35 tok/s single-stream) [FORUM 748287]. Halving tool calls from 50 to 25 cost 14 tasks. Per-command timeouts (100–300 s) have no measurable effect.

6. **Stronger teachers barely beat the 31B inside this harness.** Same YAML, 124 tasks: Gemma 31B 54/124 (two passes 54 and 53), DeepSeek V4 Pro 58/124, Qwen3.6-27B 59/123; GPT-4.1/GPT-5 "same ballpark". 15% of tasks flip between identical Gemma runs; the union of four runs is 73/123 [FORUM 747168]. The ceiling here is the harness (32k context with compaction, time, sparse issues), so **distillation buys format and procedure, not new knowledge** — and the gap between pass@1 (43%) and union (59%) is the real headroom.

7. **Graph tools are unused or broken as shipped.** In a 129-task run the model touched them on 21 tasks; **all 21 `search_similar_code` calls returned empty** (it needs a node id, not free text — there is no live embedder offline); `get_code_subgraph` was never used; no graph call returned a gold file before the first edit; the ablation was 50 vs 55 against a no-graph control [FORUM 746250]. The embeddings themselves are near-collapsed: the official notebook prints cosine 0.9996/0.9993 between a tutorial route handler and `APIRouter.__init__` / `FastAPI.setup`; a community analysis finds random-pair cosine 0.78–0.90, gold file in top-10 for 35/129 issues vs 67 for grep, and TF-IDF beating them 52% vs 9% (UNVERIFIED). The graph has only `calls` edges, no `async def` or module-level nodes, is sparser than it is large (fastapi: 4,263 nodes, 2,430 edges), and captures 14–21% of runtime call pairs (UNVERIFIED). Lexical localisation on the public set: first identifier-grep hit correct 30%; grep+BM25 fusion top-5 61%, top-10 74%; **35/128 issues contain no code identifier at all** [FORUM 746250 comment].

8. **Known harness traps (each has cost real submissions).** vLLM's gemma4 parser mangles `edit_file` calls whose `old_string` contains triple-quoted docstrings, after which the model retries the identical call up to 27×; `ParallelAgent` with tool-using sub-agents is broken in ADK 1.36.1 (host: too risky to upgrade); `max_output_tokens: 16384` overflows the 32k window; `write_file("/tmp/x")` lands in `/workspace/tmp/x` and in the patch; 26/46 patches in one host trial contained scratch files; edits to test files conflict with the hidden `test_patch` (an explicit "patch hygiene" finaliser cut conflicts from 8–11 to 2–4 tasks); exceptions once bypassed the working-tree fallback and lost edits; three consecutive turns without a tool call end the session; undeclared tool names used to kill the task; `.sh` and extensionless files fail validation. The sample submission with adapters failed outright for one user (adapter path), so **adapter loading on the scorer is unproven in public**.

### I.3 The training data we have

129 tasks (fastapi 67, rich 48, requests 13, httpx 1), 127 distinct base commits, `hints_text` empty in all 129, gold `patch` and `test_patch` present, 20.5 GiB of snapshots, graphs and embeddings per commit. Host confirms no overlap with test repos. As a *CV set* it is biased (fastapi-heavy, memorised, half-broken grader) and must be repaired, de-noised (drop empty-patch-passing tasks), reported per repo, and **supplemented with a held-out set from other repositories run through the same harness** (SWE-rebench / SWE-Gym / SWE-smith tasks with Docker images).

## Part II — What the field knows

### II.1 Gemma 4 (arXiv:2607.02770, model card, HF configs) — see `raw/02_gemma4_model.md`

- Family: E2B (2.3B eff./5.1B total, PLE), E4B (4.5B/8B), 12B (encoder-free unified), 26B-A4B (MoE, not allowed), 31B dense (60 layers, hidden 5376, 32/16 heads, 10 global layers with head_dim 512 and k=v reuse, 1024 sliding window, 5:1 local:global, 262k vocab, 256k context). QAT W4A16 compressed-tensors checkpoints exist for E2B/E4B/12B/31B only; 31B ≈ 18–22 GB.
- Official agentic numbers (thinking): LiveCodeBench v6 80.0/72.0/52.0/44.0 (31B/12B/E4B/E2B); τ²-bench avg 76.9/69.0/42.2/24.5; Terminal-Bench-Hard 36.0/18.0/8.0/3.0; RULER-128k 96.4/91.2/86.6/70.4. **No SWE-bench number was published.** Third parties: 41.6% on fresh SWE-rebench (31B, UNVERIFIED); 26B-A4B 38.7% SWE-bench Lite with a mini-swe-agent text-action scaffold but failing badly with 11 native JSON tools ("Gemma 4 can code, it just can't fill out JSON forms reliably").
- Tool format: not JSON — `<|tool_call>call:name{key:<|"|>str<|"|>}<tool_call|>`, results in `<|tool_response>`, stop ids 1 and 106; `<|think|>` in the system turn enables thinking; 12B/31B emit an empty thought block even with thinking off (include it in training data); thoughts are kept in history only inside tool-call turns. Known template bugs: content+tool_calls turns mis-rendered; multi-round tool calling stalling after one call (escalated at Google, open mid-2026).
- Post-training recipe: undisclosed ("similar to Gemma 3" plus thinking). Fine-tuning guidance: train on `-it`; for QAT serving train on **`-qat-q4_0-unquantized`** (the bf16 QAT export) because the w4a16 artifact has no training forward path; Unsloth: 31B QLoRA 22 GB, LR 2e-4 short / 2e-5 long, r 8–32, all linear layers, `train_on_responses_only`, keep ≥75% reasoning examples to preserve thinking.
- Ecosystem traps: head_dim 512 exceeds FlashAttention-2 → vLLM falls back to Triton attention (slow on L4-class); vLLM LoRA for Gemma 4 landed 2026-04-17 for the language model only, with later reports of adapters silently not applied (issues #41754, #47026) and rank-32 all-layer instability over compressed-tensors bases (#50059); five global layers have no `v_proj` (use `all-linear`); PEFT ≥ 0.19.1 for correct safetensors layout; `use_cache=False` breaks E2B/E4B.
- Throughput anchors: H100 bf16 31B 40 tok/s @c=1 / 375 @c=16 (MTP drafter 125/953); 4×L4 W4A16 31B ≈ 35 tok/s, 12B ≈ 67 tok/s [FORUM].

### II.2 SWE agents: scaffolds, training, test-time compute — see `raw/03_swe_agent_literature.md`

**Benchmarks.** SWE-bench (arXiv:2310.06770) → Verified (500, saturated: closed models 80–97%) → SWE-bench Pro (arXiv:2509.16941; private held-out split is the closest analogue to our hidden repos: frontier systems drop 35–45% relative from Verified) → SWE-rebench monthly fresh splits (arXiv:2505.20411) → SWE-bench Live. Contamination is real: 25–33% of early "solves" were leaked or weak-test artefacts (SWE-Bench+, arXiv:2410.06992); git-hacking inflates ~5 points (SWE-Lego, arXiv:2601.01426) — strip future commits/reflog in any environment we train in.

**Scaffold lessons with effect sizes.**
- *Structured tools beat bash-only for small models*: +15.0 Verified for a 30B model (harness design study, arXiv:2609.20804); bash-only is a frontier-model luxury. SWE-agent ACI ablations (arXiv:2405.15793, GPT-4-Turbo at 18%, i.e. a model roughly where a tuned 12B sits): lint-gated edit +3.0 (vs shell editing +7.7), windowed 100-line view +5.3 vs whole file, summarised search +6.0, last-5-observation history +3.0, in-context demo +1.7.
- *Context management is mostly about not dying*: unmanaged 32k windows overflow in 78.7% of runs; managed vs not = +35.7 at 32k, +2.7 at 128k; "recall elided content" tools go unused; learned compaction +9.2 (AutoCompact, arXiv:2610.02163). Our harness already compacts at 14k/keep-5 — so **the agent must keep its state on disk (notes file, checkpointed diff), not in chat history.**
- *Agentless* (arXiv:2407.01489): fixed localise→repair→validate pipeline; skeleton format beats full files (58.3 vs 53.7 element recall at 7× lower cost); LLM-over-repo-tree 78.7 file recall, +embedding 81.7; selection ladder majority 25.7 → +regression tests 27.0 → +reproduction tests 32.0 (oracle 42.0). Kimi-Dev shows an Agentless-style prior makes later agent SFT ~30× more token-efficient.
- *Reproduce first / checkpoint the diff*: 60–69% of failures edit the right code and then thrash it; checkpointing the diff when a self-written repro flips to pass recovered 5/5 gold-then-destroyed cases (Coherence Collapse, arXiv:2603.24631); TestPrune +9–13% relative by recovering unsubmitted fixes.
- *Loops*: >25% of SWE-agent-LM-32B trajectories contain a repeated action sequence of length ≥10, which implies 89% failure; 53% of its failures were budget exhaustion (SWE-smith). A loop penalty in RL cut loops 31% → 0.8% and halved steps (SWE-Protégé, arXiv:2602.22124).
- *Trajectory length*: resolved SWE-agent runs median 12 turns; 80–90% of what a model will ever solve it solves within 30–40 tool calls; Devstral saturates at 50 turns.

**Training small open models (the core of the competition).**
- *Data scale*: 491 teacher trajectories → +8.8/+12.4/+13.6 Verified at 7B/14B/32B (SWE-Gym, arXiv:2412.21139); 500 → 28.2, 5,016 → 40.2 at 32B, log-linear (SWE-smith, arXiv:2504.21798); 14B saturates ~800 trajectories (R2E-Gym, arXiv:2504.07164); 8B reaches 39–42% with 18k–66k (SWE-Lego, Kwai-Klear). **For a ≤12B model the first 500–1,000 good trajectories buy most of the gain; 2k–5k is the knee.**
- *Repo diversity is the lever, not repo depth*: Verified improves ~log(#repos) (SWE-smith); variety significant, density not (SWE-Bench++, arXiv:2512.17419); specialisation only helps on the specialised repo (+7.6/+9.1 on SymPy). Mixing 868 on-policy trajectories from 11 repos *dropped* SWE-Gym's Lite score 15.3 → 8.7. **Our four repos should supply environments and format, not the bulk of diversity.**
- *Quality curation past ~2k*: error masking +2.0–2.2, semi-resolved (right localisation, wrong fix) +1.2 (SWE-Lego); 10% curated beats 100% (SWE-Prime, arXiv:2608.27449); process-aware 3k beats random 3k by +8 (FLARE); error-retry rate is the best single quality feature for LoRA at 7B (arXiv:2607.17205); task difficulty does not matter, issue-text style does (SWE-smith).
- *Scaffold mismatch costs 2–6 points* (Open-SWE-Traces, arXiv:2606.16038); Devstral trained in both XML and native formats to generalise. One datapoint says LoRA/QLoRA underperformed full SFT at 7B (SWE-Protégé) — spend LoRA capacity on format and procedure, all linear layers, moderate rank.
- *RL*: works at 32B+ (DeepSWE 23 → 42 in 200 steps, ~9k H100-hours; SkyRL 4.6k H100-h; Nebius 128×H200), modest at 14B, no pure-RL success below 14B; SWE-Master 4B SFT 27.6 → RL 33.4; Agent Lightning 9B 41.8 → 56.4 with "modest" compute (UNVERIFIED) and is the only framework that wraps an *existing* harness via an LLM-endpoint proxy. Shaped behavioural rewards (loop/length penalty, format validity, no test edits) are cheap and large. SWE-RL's diff-similarity reward needs no execution infra.
- *Test-time compute*: most gains by K=8; K=3 with a cheap selector beats 40-patch majority vote (Kimi-Dev); hybrid execution + execution-free verifiers best (R2E-Gym 51.0 vs 43.7/42.8); execution-free verifiers need the thoughts, not just the patch; re-running empty-patch instances +3.8 (Devstral); prefix replay −17% cost (SWE-Replay, arXiv:2601.22129); a 0.6B failure monitor +5.2 at 25% FPR (Fail-Fast, arXiv:2608.03222). Under our 5.5-min cap a second full attempt is unaffordable on the 31B; it may be affordable on the 12B.
- *Open datasets* (licence-clean for an Apache-2.0 release): `nvidia/Open-SWE-Traces` (151k–263k, CC BY, open teachers, 9 languages), `nvidia/SWE-Hero` (34k) and `Nemotron-SFT-SWE-v2` (46k agentic + 210k agentless, incl. localisation/edit splits), `nebius/SWE-rebench-openhands-trajectories` (67k, Qwen3-Coder-480B), `Kwai-Klear` 66k mini-swe-agent (MIT), `SWE-bench/SWE-smith-trajectories` (5k, MIT but Claude-generated → ToS risk), `internlm/SWE-Fixer-Train-110K` (MIT; retrieval + editing supervision). Task pools with Docker images: `nebius/SWE-rebench` (21k, ~7.5k images), `SWE-Gym` (2.4k), `SWE-smith` (50k), `R2E-Gym` (4.6k).

### II.3 Localisation and code graphs — see `raw/04_code_graph_retrieval.md`

- Localisation bounds resolution: Agentless' patches hit the right file 69.7%, function 52.0%, line 35.3%; better localisers raise pass@1 modestly and pass@k a lot (LocAgent Table 8; OrcaLoca +6.3; ToolTrain-7B 14.0 vs 7.6).
- **LocAgent (arXiv:2503.09089) is the closest prior art to our tools**: Python AST graph (file/class/function; contain/import/invoke/inherit), three read-only tools (`SearchEntity`, `TraverseGraph` with hops/direction/type, `RetrieveEntity`), tree-formatted output. A **LoRA-tuned 7B** reaches 88.3 file Acc@5 / 71.5 function Acc@10 on Lite at $0.05 and 6 rounds (Claude-3.5: 94.2/77.4; BM25 61.7/36.9; dense 84.7/58.8). Ablation: removing keyword search −18 function points; removing traversal −5; fixing hops=1 −5. Trained on ~430 Claude trajectories + 335 self-sampled.
- Graph exposure rules: prompt-stuffing 2-hop neighbourhoods *hurts* (RepoGraph k=2 26.0 vs 29.67 baseline, arXiv:2410.14684); on-demand fixed-signature tools work for 7B-class models (LocAgent, ARISE, Codebase-Memory); making a weak model write Cypher collapses it (CodexGraph Qwen2-72B 1.95%); indented trees beat edge lists for LLM consumption. "Code Isn't Memory" (arXiv:2606.22417) lifts localisation acc@5 44.3 → 84.5 even for a frontier model with a structural index.
- Inference-time algorithms that cost zero tool calls on our NetworkX graph: personalised PageRank from weighted seeds (Aider, FeatLens, HippoRAG), OrcaLoca distance-aware pruning to ~12 items (+4.3), CoSIL accept/reject frontier expansion capped at 10 iterations, test-call-chain seeds (IssueExec +17 resolved on Lite).
- Query side matters more than the embedding model: raw issue text is a weak query; identifier extraction/reformulation +35% first-file ranking (arXiv:2512.07022); multi-query + reciprocal rank fusion; code-shaped (HyDE-style) queries are a plausible but untested hypothesis for a function-level code index. Benchmarks reward keyword shortcuts (LogicLoc, arXiv:2604.16021): exploit identifiers when present, spend graph budget only when absent.
- Training a localiser: ToolTrain (arXiv:2508.03012) uses nDCG over gold-patch functions as an RL reward (7B → 83.1 file / 62.4 function Recall@5 on Verified); A²Agent (arXiv:2608.29831) gets a **Qwen3-4B with graph tools** to beat 8× larger baselines with discover+commit rewards; gold-patch → AST-node mapping is the standard labelling recipe and is cheap on our 129 tasks.

### II.4 Training recipes and data pipelines — see `raw/05_training_recipes_and_data.md`

- Convert every external trajectory into the competition's 9 tool names and JSON observation shapes, render with the exact Gemma 4 V2 chat template, keep thinking content in tool-call turns, mask tool outputs and error turns, and **render contexts compaction-shaped** (summary block + last ≤5 events) so training matches what the model sees at test time.
- Published hyper-parameters: SWE-Gym Moatless LoRA r64, LR 5e-4, 5 epochs, single H100; SWE-smith/Skywork LR 5e-5, 3 epochs, 32k; Unsloth Gemma 4 LR 2e-4 short / 2e-5 long; community 31B QLoRA r16 rsLoRA LR 1e-4 2 epochs. Trajectory lengths: SWE-Gym mean 18.6k tokens (median 16k, max 81k); Nebius resolved avg 8.4k.
- Compute: 3k × 16k tokens ≈ 48M tokens/epoch → 31B QLoRA on one H100 ≈ 7–11 h/epoch, 12B ≈ 3.5–4.5 h, E4B ≈ 1.5 h (UNVERIFIED extrapolations). Rollouts at ~350k tokens each are the expensive part: 8 × 129 tasks ≈ 360M tokens ≈ 250 H100-hours — use 2–4 rollouts and teacher APIs.
- Multi-LoRA: no direct specialist-vs-generalist ablation exists; every extra LLM call costs ~90 s on the 31B; recommended shape is one generalist adapter plus at most one small tool-free localiser adapter invoked once.

## Part III — Synthesis

(The brief asked for "the synthesis on the field"; this is it.)

### III.1 The thesis

The competition is **not** "who has the best coding model". The 31B already solves ~43% of the public tasks locally and frontier teachers only reach ~47% inside the same harness. The hidden score is ~0.2 because of three multiplicative losses, in this order of size:

1. **Domain shift** from four memorised, famous repos to private, synchronous, unfamiliar ones (transfer ratio 1/3.5–1/5 observed). Everything tuned to fastapi/rich is wasted. The remedy is *repository-agnostic procedure*: grep/AST-first localisation, reproduce-first, minimal edits, nearest-test verification — trained on **diverse** external trajectories, evaluated on **held-out repos through the same harness**.
2. **Process failures that are invisible locally**: time-cap timeouts at 5.5 min, test-file edits conflicting with the hidden test patch, scratch files in the diff, lost edits on exceptions, identical-call spins, parser-mangled `edit_file` calls, nudge exhaustion. Each is worth 1–5 tasks and all are fixable by engineering and by training the format.
3. **Sampling noise**: 15% of tasks flip between identical runs; the pass@1-to-union gap is 43% → 59%. Anything that makes the policy more *consistent* (lower-entropy procedure, checkpoint-and-submit, loop guards) converts union into pass@1 without new capability.

The forum consensus ("gains will come from post-training, not harness engineering") is half right: post-training is the lever, but **what it must teach is robustness and procedure under this harness's constraints**, because that is where the points are leaking.

### III.2 Ranked design decisions (with the evidence each rests on)

1. **Model: run the 31B and the 12B head-to-head on a held-out CV under the 5.5-min cap; default to 31B.** 31B is the strongest base (Terminal-Bench-Hard 36 vs 18; 43% local) but leaves room for only one ~45-call attempt at 35 tok/s. The 12B is 1.9× faster, allowing a localiser call plus retries or a second attempt, and the literature says a tuned 12B-class model closes most of the gap on procedure (LocAgent-7B, SWE-Lego-8B). Decide by week 4 (see GPU plan).
2. **Thinking ON, budget 2,048–4,096, thought summaries ON, T≈0.7–1.0, top-p 0.95, `max_output_tokens` ≤ 8,192.** +20 points [FORUM]; 16,384 output overflows the window.
3. **Budget: `max_time_minutes` 5.0–5.5, `max_tool_calls` 45–60, `max_turns` 70–90, `timeout_seconds` 150–180.** Train the policy to finish in ≤35 calls; keep a hard "submit best checkpoint at 80% of time" rule. Failing tasks consume 81% of total time — stop them early.
4. **Patch hygiene as a trained behaviour and a scripted finaliser (skill script):** never edit tests/config files, `git checkout` them before submit, scratch only under real `/tmp` via `run_command`, `submit_patch()` right after each meaningful edit and once more at the end, end with a text-only reply. Worth 2–8 tasks [FORUM 747857] and removes the lost-edit failure mode.
5. **Localisation sub-pipeline as a deterministic skill script, not model improvisation** (raw/04 §F.2): parse anchors from the issue → grep/`git grep` seeds (weight 1.0) → `search_similar_code` only with node-id-shaped queries, multi-query, RRF (weight = similarity) → test-file seeds → local personalised PageRank + distance pruning on the NetworkX graph → skeleton rerank by the model → open ≤3 bodies. Budget 4–8 calls. Evidence: LocAgent ablations, Agentless skeletons, OrcaLoca pruning, grep+BM25 already reaching 74% top-10 on the public set. **Precondition:** verify what `search_similar_code` actually accepts and whether the graph/embedding files are reachable from `run_skill_script` (open question #2 below).
6. **SFT data: 4–6k examples, ~80% from diverse external corpora re-targeted to the 9 ADK tools, ~20% procedure supervision (localisation labels from gold patches, `edit_file` reconstructions of gold hunks, hygiene negatives), plus ~150–300 in-harness teacher trajectories on the 129 tasks and ~500 SWE-rebench tasks so the model sees real tool JSON and compaction summaries.** Keep trajectories ≤40 turns / ≤20k tokens; ≤3 per instance; error-mask; include semi-resolved; 5–10% generic Gemma-format tool-calling replay. Teachers: open-weight (DeepSeek-V4, Qwen3.6, GLM) or Gemini, to keep the Apache-2.0 release clean.
7. **Training: QLoRA (NF4) on `gemma-4-31B-it-qat-q4_0-unquantized`, r 32–64, α = r…2r, all language linear layers, vision off, LR 1e-4, 2 epochs, 24k context, response-only loss; bf16 LoRA for the 12B at 32k.** Validate every checkpoint with (a) a temperature-0 base-vs-adapter diff *in vLLM 0.19.1 with the gemma4 parsers* (silent-no-op adapter bugs exist), (b) a 30-task smoke run counting parser rejections before counting resolutions.
8. **Round 2: rejection-sampling fine-tuning** on filtered self-rollouts (resolved, no test edits, no loops, short) from external task pools, not only our four repos (SWE-Gym's on-policy collapse). **Round 3 (optional): KTO/ENTROPO-style pairs** from teacher-resolved vs self-failed trajectories. Online GRPO is out of scope on one H100 unless an Agent-Lightning-style proxy around `swegemma` exists by week 5.
9. **Agent topology: single `LlmAgent` root with at most one tool-free, `include_contents: none` localiser `agent_tool` (`skip_summarization: true`), invoked once.** Sub-agents share the budget, add ~90 s per call, are never compacted, and `ParallelAgent` is broken.
10. **Context discipline inside the harness:** system prompt + tree + issue ≤ 4k tokens; a one-paragraph plan written to `/tmp/notes.md` and re-read after compaction; small `read_file` windows; never `search_similar_code` on huge nodes; prefer `read_file` + small `old_string` anchors over docstring-spanning edits (parser bug).
11. **Loop and malformed-call defences in the prompt and in training data:** never repeat an identical call; never resend a rejected call; JSON-typed arguments; shell only inside `run_command`. Rules like these cut malformed calls 21% → 1.4% in one entrant's runs; a length-10 repetition means 89% failure.
12. **Evaluation protocol:** repaired 129-task grader minus empty-patch-passing tasks, per-repo breakdown, **plus ≥100 held-out tasks from other repos through the same harness and the same 5.5-min cap**, 2 seeds, paired McNemar before adopting any change (run-to-run noise is ±5–8 tasks on 129). Treat the public LB as a sanity check, not a signal.

### III.3 Paper Track: a second, cheaper prize

245 submissions compete for three awards ($15k/$10k/$10k) judged on novelty, generality, relevance, verifiability, clarity; the judges are Google's graph-ML group (Perozzi, Galkin, Rózemberczki) and the call explicitly favours work on the released graphs and embeddings. Material we already have or will produce as a by-product qualifies for **Best New Resource**: (a) a repaired, de-noised grader and per-task soundness labels for the 129 public tasks; (b) a localisation benchmark derived from gold patches (issue → graph nodes) with grep/BM25/embedding/PPR baselines; (c) an analysis of the shipped embeddings' anisotropy and how centring/whitening or query reformulation changes retrieval; (d) the ADK-format trajectory corpus and conversion tooling. Deadline **Nov 12**, ≤3,000 words. Budget one person-week; start the write-up skeleton in week 2.

### III.4 Open questions to settle in the first days (ordered by how much they change the design)

1. Does the scorer's vLLM 0.19.1 actually apply a dense Gemma 4 LoRA on the W4A16 base, and at what rank/latency cost? (Temperature-0 A/B on the exact wheelhouse; measure decode slowdown at r16/32/64.)
2. What does `search_similar_code(query)` do with free text vs a node id, is there any offline encoder, and are `graphs/` + `embeddings/` readable from `run_skill_script` inside the sandbox? (Determines whether the localisation pipeline can post-process embeddings — e.g. mean-centre them — in a skill script.)
3. Does ADK compaction fire *within* a task on the scorer path (interval 5 vs 15; one camp says trajectories simply die at 32k)? Design for the pessimistic case either way.
4. Exact nudge texts, whether a `skip_summarization` sub-agent return counts as a no-tool turn, and `max_turns` semantics across the agent tree.
5. Whether skill-script invocations count against `max_tool_calls`, the `references/` vs `resources/` directory name, and whether sub-agents may declare `skills:`.
6. Real 4×L4 tokens/s for 12B vs 31B *with an adapter attached* and with thinking, so the time cap can be set per model.
7. Whether the host's fix to the public training tasks has landed (re-download `wheels/` and re-run the gold-patch check before trusting any local number).
